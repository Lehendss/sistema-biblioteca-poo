1. Descripción de la solución

Se desarrolló un sistema de biblioteca que permite registrar materiales, usuarios y préstamos. Se seleccionó este caso porque permite demostrar los principios fundamentales de la programación orientada a objetos mediante un flujo funcional y fácil de explicar.

La biblioteca administra un catálogo con libros y revistas, registra usuarios y controla el préstamo y la devolución de materiales.

2. Semana 1: clases, objetos y encapsulación

Las clases Persona y Material son las clases base del modelo. Sus atributos se almacenan como privados mediante nombres con doble guión bajo. El acceso se controla mediante propiedades @property, que funcionan como getters y setters.

ClaseResponsabilidadEncapsulación
PersonaRepresentar los datos comunes de una persona.Identificación, nombre y correo privados con validaciones.
MaterialRepresentar un recurso prestable.Código, título y disponibilidad privados.
BibliotecaCoordinar el catálogo, usuarios y préstamos.Sus colecciones internas no se exponen directamente.

3. Semana 2: herencia y composición

Herencia

Usuario y Bibliotecario heredan de Persona. Libro y Revista heredan de Material. De esta forma, las subclases reutilizan atributos y métodos comunes y agregan sus características específicas.

Composición

Biblioteca compone un objeto Catalogo y una colección de objetos Prestamo. Cada préstamo relaciona un Usuario con un Material. La biblioteca coordina el ciclo completo: registrar, prestar y devolver.

RelaciónTipoDescripción
Persona -> UsuarioHerenciaUn usuario es una persona con capacidad de solicitar materiales.
Material -> LibroHerenciaUn libro es un material con autor e ISBN.
Biblioteca -> CatalogoComposiciónLa biblioteca administra su catálogo de materiales.
Prestamo -> Usuario y MaterialAsociaciónEl préstamo registra quién recibe qué material.

5. Funcionamiento

  1. Se crea una biblioteca.
  2. Se registran un libro y una revista.
  3. Se registra un usuario y un bibliotecario.
  4. El usuario solicita un libro.
  5. La biblioteca crea el préstamo y marca el libro como no disponible.
  6. Se devuelve el libro y vuelve a estar disponible.
  7. Se controla el intento de devolver nuevamente un libro sin préstamo activo.
Ejecución: desde la carpeta del proyecto se puede ejecutar python3 -m src.main y verificar el funcionamiento con python3 -m unittest discover -s tests -v.

6. Conclusión

La solución separa responsabilidades: los materiales controlan su disponibilidad, las personas mantienen sus datos y la biblioteca coordina las operaciones. La herencia evita duplicar atributos comunes y la composición permite que la biblioteca administre el catálogo y los préstamos. El uso de atributos privados y validaciones protege el estado interno y facilita ampliar el sistema con nuevos tipos de materiales o roles.
